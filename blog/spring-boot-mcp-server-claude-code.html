Turn a Spring Boot service into an MCP server Claude Code can call (Spring AI 2.1)

November 26, 2026 · 5 min read

A coding agent can read your code, but it can't see what your service knows at runtime. MCP (Model Context Protocol) lets it ask: your app publishes tools, and a client such as Claude Code can list and call them. In Spring AI 2.1.0 that takes one starter, one annotated method, and one property that is easy to miss. Without it, /mcp returns 404.

Everything shown here was run on JDK 17 with Spring AI 2.1.0 and Spring Boot 4.2.0. No LLM API key is involved.

<dependencies>

    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

The spring-ai-bom manages Spring AI versions only; it does not bring in Spring Boot. Here the Boot version comes from spring-boot-starter-parent 4.2.0, which matches what the MCP starter's own dependencies declare.

One tool

Next to the usual @SpringBootApplication class, a record and an in-memory service are enough:

package com.example.orders;

import java.math.BigDecimal;

public record Order(String id, String customer, String status, BigDecimal total) {
}
package com.example.orders;

import java.math.BigDecimal;
import java.util.Map;

import org.springframework.ai.mcp.annotation.McpTool;
import org.springframework.ai.mcp.annotation.McpToolParam;
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    private final Map<String, Order> orders = Map.of(
            "ORD-1001", new Order("ORD-1001", "Ana", "SHIPPED", new BigDecimal("149.90")),
            "ORD-1002", new Order("ORD-1002", "Bruno", "PAYMENT_PENDING", new BigDecimal("39.00")));

    @McpTool(name = "get_order",
            description = "Look up one order by its id and return its customer, status and total",
            annotations = @McpTool.McpAnnotations(readOnlyHint = true, destructiveHint = false))
    public Order getOrder(
            @McpToolParam(description = "Order id, for example ORD-1001", required = true) String orderId) {
        Order order = orders.get(orderId);
        if (order == null) {
            throw new IllegalArgumentException("No order with id " + orderId);
        }
        return order;
    }
}

@McpTool and @McpToolParam live in org.springframework.ai.mcp.annotation. The descriptions are what a client receives to decide when to call the tool and what to pass, so write them for that reader.

The property you can't skip

Start with only a server name:

spring.ai.mcp.server.name=orders

The app starts and logs Registered tools: 1. But a request to /mcp fails:

With only the name set, 2.1.0 starts the older SSE transport. /sse answers 200 and /mcp doesn't exist.

This is confusing because the configuration metadata lists streamable as the default value of spring.ai.mcp.server.protocol. The auto-configuration conditions say otherwise: the SSE one has matchIfMissing=true, and the streamable one has matchIfMissing=false. If you set nothing, SSE wins.

The fix is the second line:

spring.ai.mcp.server.name=orders
spring.ai.mcp.server.protocol=streamable

(In 2.1.0, the sse-endpoint and sse-message-endpoint properties are also marked deprecated.)

A test that talks MCP

The test boots the app on a random port and uses the MCP Java SDK client to list the tools and call one. This is the body of the test method, inside a @SpringBootTest with webEnvironment = RANDOM_PORT:

var transport = HttpClientStreamableHttpTransport.builder("http://localhost:" + port).build();
try (McpSyncClient client = McpClient.sync(transport).build()) {
    client.initialize();

    assertThat(client.listTools().tools())
            .extracting(McpSchema.Tool::name)
            .containsExactly("get_order");

    var result = client.callTool(McpSchema.CallToolRequest.builder("get_order")
            .arguments(Map.of("orderId", "ORD-1002"))
            .build());

    assertThat(result.isError()).isNotEqualTo(Boolean.TRUE);
    assertThat(result.content().get(0).toString()).contains("PAYMENT_PENDING");
}

✔ Connected means the CLI reached the server and the health check passed. We did not run a Claude Code session that calls get_order, so this post shows no such output. The tool calls proven here are the ones made by curl and by the JUnit test.

One more thing from the logs: the app printed a few Tomcat Error setting socket options lines around the time of the CLI checks. The server still showed as connected. We did not investigate the cause.

Before you expose anything real

  • There is no authentication in this example. Use it on localhost only. Spring Boot listens on all network interfaces by default, so consider server.address=127.0.0.1 (not part of the runs above).
  • Start with read-only tools. readOnlyHint is a description for the client, not a permission check. A method that writes data needs real authorization on your side.
  • Return only what the caller needs. Whatever a tool returns can end up in the model's context.
