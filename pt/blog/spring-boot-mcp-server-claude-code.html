Transforme um serviço Spring Boot em um servidor MCP que o Claude Code pode chamar (Spring AI 2.1)

26 de novembro de 2026 · 5 min de leitura

Um agente de código consegue ler o seu código, mas não enxerga o que o serviço sabe em tempo de execução. O MCP (Model Context Protocol) permite que ele pergunte: a aplicação publica ferramentas, e um cliente como o Claude Code pode listá-las e chamá-las. No Spring AI 2.1.0 isso pede um starter, um método anotado e uma propriedade fácil de esquecer. Sem ela, /mcp responde 404.

Tudo o que aparece aqui foi executado no JDK 17 com Spring AI 2.1.0 e Spring Boot 4.2.0. Nenhuma chave de API de LLM é usada.

Dependências

<parent>

    <artifactId>spring-boot-starter-parent</artifactId>

    <relativePath/>
</parent>

<properties>
    <java.version>17</java.version>
    <spring-ai.version>2.1.0</spring-ai.version>

            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

O spring-ai-bom só gerencia versões do Spring AI; ele não traz o Spring Boot. Aqui a versão do Boot vem do spring-boot-starter-parent 4.2.0, a mesma que as próprias dependências do starter de MCP declaram.

Uma ferramenta

Além da classe @SpringBootApplication de sempre, um record e um serviço em memória bastam:

package com.example.orders;

import java.math.BigDecimal;

public record Order(String id, String customer, String status, BigDecimal total) {
}
package com.example.orders;

import java.math.BigDecimal;
import java.util.Map;

import org.springframework.ai.mcp.annotation.McpTool;
import org.springframework.ai.mcp.annotation.McpToolParam;
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    private final Map<String, Order> orders = Map.of(
            "ORD-1001", new Order("ORD-1001", "Ana", "SHIPPED", new BigDecimal("149.90")),
            "ORD-1002", new Order("ORD-1002", "Bruno", "PAYMENT_PENDING", new BigDecimal("39.00")));

    @McpTool(name = "get_order",
            description = "Look up one order by its id and return its customer, status and total",
            annotations = @McpTool.McpAnnotations(readOnlyHint = true, destructiveHint = false))
    public Order getOrder(
            @McpToolParam(description = "Order id, for example ORD-1001", required = true) String orderId) {
        Order order = orders.get(orderId);
        if (order == null) {
            throw new IllegalArgumentException("No order with id " + orderId);
        }
        return order;
    }
}

@McpTool e @McpToolParam ficam em org.springframework.ai.mcp.annotation. As descrições são o que o cliente recebe para decidir quando chamar a ferramenta e o que passar, então escreva pensando nesse leitor.

A propriedade que não dá para pular

Comece só com o nome do servidor:

spring.ai.mcp.server.name=orders

Só com o nome configurado, a 2.1.0 sobe o transporte antigo, SSE. /sse responde 200 e /mcp não existe.

Isso confunde porque os metadados de configuração listam streamable como valor padrão de spring.ai.mcp.server.protocol. As condições da autoconfiguração dizem outra coisa: a do SSE tem matchIfMissing=true e a do streamable tem matchIfMissing=false. Se você não define nada, o SSE vence.

A correção é a segunda linha:

spring.ai.mcp.server.protocol=streamable

(Na 2.1.0, as propriedades sse-endpoint e sse-message-endpoint também estão marcadas como deprecated.)

Um teste que fala MCP

O teste sobe a aplicação em uma porta aleatória e usa o cliente do MCP Java SDK para listar as ferramentas e chamar uma delas. Este é o corpo do método de teste, dentro de um @SpringBootTest com webEnvironment = RANDOM_PORT:

var transport = HttpClientStreamableHttpTransport.builder("http://localhost:" + port).build();
try (McpSyncClient client = McpClient.sync(transport).build()) {
    client.initialize();

    assertThat(client.listTools().tools())
            .extracting(McpSchema.Tool::name)
            .containsExactly("get_order");

    var result = client.callTool(McpSchema.CallToolRequest.builder("get_order")
            .arguments(Map.of("orderId", "ORD-1002"))
            .build());

    assertThat(result.isError()).isNotEqualTo(Boolean.TRUE);
    assertThat(result.content().get(0).toString()).contains("PAYMENT_PENDING");
}

Conecte o Claude Code

Com a aplicação ainda rodando, registre o servidor. Isto foi executado com o Claude Code 2.1.220:

✔ Connected significa que a CLI alcançou o servidor e a verificação de saúde passou. Não rodamos uma sessão do Claude Code chamando get_order, então este post não mostra essa saída. As chamadas de ferramenta comprovadas aqui são as feitas pelo curl e pelo teste JUnit.

Mais um detalhe dos logs: a aplicação imprimiu algumas linhas Error setting socket options do Tomcat por volta do momento das verificações da CLI. O servidor continuou aparecendo como conectado. Não investigamos a causa.

Antes de expor algo real

  • Este exemplo não tem autenticação. Use apenas em localhost. O Spring Boot escuta em todas as interfaces de rede por padrão, então considere server.address=127.0.0.1 (não fez parte das execuções acima).
  • Comece com ferramentas somente de leitura. readOnlyHint é uma descrição para o cliente, não uma checagem de permissão. Um método que grava dados precisa de autorização de verdade do seu lado.
  • Retorne só o que quem chama precisa. O que uma ferramenta devolve pode acabar no contexto do modelo.
