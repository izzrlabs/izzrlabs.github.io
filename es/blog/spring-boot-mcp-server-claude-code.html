Convierte un servicio Spring Boot en un servidor MCP que Claude Code puede llamar (Spring AI 2.1)

26 de noviembre de 2026 · 5 min de lectura

Un agente de programación puede leer tu código, pero no ve lo que tu servicio sabe en tiempo de ejecución. MCP (Model Context Protocol) le permite preguntar: tu aplicación publica herramientas, y un cliente como Claude Code puede listarlas y llamarlas. En Spring AI 2.1.0 eso requiere un starter, un método anotado y una propiedad fácil de pasar por alto. Sin ella, /mcp responde 404.

Todo lo que ves aquí se ejecutó en JDK 17 con Spring AI 2.1.0 y Spring Boot 4.2.0. No se usa ninguna clave de API de un LLM.

Dependencias

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.2.0</version>
    <relativePath/>
</parent>

<properties>
    <java.version>17</java.version>
    <spring-ai.version>2.1.0</spring-ai.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

El spring-ai-bom solo gestiona versiones de Spring AI; no incluye Spring Boot. Aquí la versión de Boot viene de spring-boot-starter-parent 4.2.0, la misma que declaran las propias dependencias del starter de MCP.

Una herramienta

Además de la clase @SpringBootApplication de siempre, basta con un record y un servicio en memoria:

package com.example.orders;

import java.math.BigDecimal;

public record Order(String id, String customer, String status, BigDecimal total) {
}
package com.example.orders;

import java.math.BigDecimal;
import java.util.Map;

import org.springframework.ai.mcp.annotation.McpTool;
import org.springframework.ai.mcp.annotation.McpToolParam;
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    private final Map<String, Order> orders = Map.of(
            "ORD-1001", new Order("ORD-1001", "Ana", "SHIPPED", new BigDecimal("149.90")),
            "ORD-1002", new Order("ORD-1002", "Bruno", "PAYMENT_PENDING", new BigDecimal("39.00")));

    @McpTool(name = "get_order",
            description = "Look up one order by its id and return its customer, status and total",
            annotations = @McpTool.McpAnnotations(readOnlyHint = true, destructiveHint = false))
    public Order getOrder(
            @McpToolParam(description = "Order id, for example ORD-1001", required = true) String orderId) {
        Order order = orders.get(orderId);
        if (order == null) {
            throw new IllegalArgumentException("No order with id " + orderId);
        }
        return order;
    }
}

@McpTool y @McpToolParam están en org.springframework.ai.mcp.annotation. Las descripciones son lo que recibe el cliente para decidir cuándo llamar a la herramienta y qué pasarle, así que escríbelas pensando en ese lector.

La propiedad que no puedes omitir

Empieza solo con el nombre del servidor:

spring.ai.mcp.server.name=orders

La aplicación arranca y registra Registered tools: 1 en el log. Pero una petición a /mcp falla:

Con solo el nombre configurado, la 2.1.0 levanta el transporte antiguo, SSE. /sse responde 200 y /mcp no existe.

Esto confunde porque los metadatos de configuración indican streamable como valor por defecto de spring.ai.mcp.server.protocol. Las condiciones de la autoconfiguración dicen otra cosa: la de SSE tiene matchIfMissing=true y la de streamable tiene matchIfMissing=false. Si no defines nada, gana SSE.

La solución es la segunda línea:

spring.ai.mcp.server.name=orders
spring.ai.mcp.server.protocol=streamable

(En la 2.1.0, las propiedades sse-endpoint y sse-message-endpoint también están marcadas como deprecated.)

Un test que habla MCP

El test arranca la aplicación en un puerto aleatorio y usa el cliente del MCP Java SDK para listar las herramientas y llamar a una. Este es el cuerpo del método de test, dentro de un @SpringBootTest con webEnvironment = RANDOM_PORT:

var transport = HttpClientStreamableHttpTransport.builder("http://localhost:" + port).build();
try (McpSyncClient client = McpClient.sync(transport).build()) {
    client.initialize();

    assertThat(client.listTools().tools())
            .extracting(McpSchema.Tool::name)
            .containsExactly("get_order");

    var result = client.callTool(McpSchema.CallToolRequest.builder("get_order")
            .arguments(Map.of("orderId", "ORD-1002"))
            .build());

    assertThat(result.isError()).isNotEqualTo(Boolean.TRUE);
    assertThat(result.content().get(0).toString()).contains("PAYMENT_PENDING");
}

Con la aplicación todavía en marcha, registra el servidor. Esto se ejecutó con Claude Code 2.1.220:

✔ Connected significa que la CLI llegó al servidor y la comprobación de estado pasó. No ejecutamos una sesión de Claude Code que llame a get_order, así que este artículo no muestra esa salida. Las llamadas a la herramienta que se prueban aquí son las hechas con curl y con el test de JUnit.

Un detalle más de los logs: la aplicación imprimió algunas líneas Error setting socket options de Tomcat alrededor del momento de las comprobaciones de la CLI. El servidor siguió apareciendo como conectado. No investigamos la causa.

Antes de exponer algo real

  • Este ejemplo no tiene autenticación. Úsalo solo en localhost. Spring Boot escucha en todas las interfaces de red por defecto, así que considera server.address=127.0.0.1 (no formó parte de las ejecuciones anteriores).
  • Empieza con herramientas de solo lectura. readOnlyHint es una descripción para el cliente, no un control de permisos. Un método que escribe datos necesita autorización real de tu lado.
  • Devuelve solo lo que necesita quien llama. Lo que devuelve una herramienta puede acabar en el contexto del modelo.
